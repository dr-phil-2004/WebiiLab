# WebiiLab — agent guide

Webinar platform: presenters create webinars, attendees join a live stream
(Stream Video + Chat), and a CTA sells a Stripe product or books a call.
Stack: Next.js 16 (App Router), React 19, TypeScript strict, Prisma 7 +
Postgres, Clerk auth, Stripe (+ Connect), Stream, Zustand, Tailwind 4,
shadcn components on **Base UI**.

## Definition of done

A change is done only when this passes, run from `next-webiilabapp/`:

```bash
npm run verify   # prisma generate + typecheck + lint + tests
```

CI runs the same command on every PR. Do not report a task as finished, and do
not open a PR, while it fails. If you fix a bug, add a test that fails without
your fix (see `app/api/stripe-webhook/route.test.ts`).

Other commands: `npm run dev`, `npm run test`, `npm run lint`, `npm run typecheck`.

## Where things live

- `app/actions/*.ts` — server actions. All DB, Stripe and Stream server calls go here.
- `app/api/*/route.ts` — webhooks (Stripe).
- `app/(protectedRoutes)` — presenter dashboard (Clerk-protected).
- `app/(publicRoutes)/live-webinar` — attendee side.
- `components/ui` — generated by the shadcn CLI. Don't hand-edit unless necessary.
- `lib/generated/prisma` — generated, git-ignored. Run `npm run db:generate`.
- `store/` — Zustand stores (client state only).

## Conventions (enforced by lint where possible)

- **Base UI, not Radix.** Never write `asChild`. Use `render={<Element />}`;
  on `<Button>` rendering a link, add `nativeButton={false}`.
- **Server-only code stays on the server.** In `components/`, `store/`,
  `hooks/`, `_components/`: no `@/lib/prismaClient`, no `@/lib/stripe`, no
  `@stream-io/node-sdk`. Use `import type` for `stripe` and Prisma models;
  import Prisma enums from `@/lib/generated/prisma/enums`.
- **No `any`, no `type Props = {}`.** A component without props takes no
  argument. Narrow unknown API shapes with a small local type.
- **`switch` cases never fall through silently** (Stripe webhook bug).
- Components are PascalCase. A file named `page.tsx` is a route — never use it
  for a component inside `_components/`; use `index.tsx` or `Name.tsx`.
- Server actions return `{ success, status, data? , error? }`; don't throw to the client.
- Don't leave commented-out code or comments that explain a workaround: fix
  the cause, or open an issue. The next agent copies whatever is in the repo.

## Correction ladder (how to fix a recurring agent mistake)

When you correct the same mistake twice, move the fix up this list instead of
repeating it in chat:

1. **Architecture / types** — make the mistake impossible to write.
2. **Lint / TypeScript / CI** — `eslint.config.mjs` (add a rule with a message
   explaining the right way).
3. **This file** — only for what can't be checked mechanically.
4. **Code review** — to discover new rules, not to enforce old ones.

Lint warnings are capped (`--max-warnings` in `package.json`). When you remove
warnings, lower the cap; never raise it.

## Known debt (don't copy these patterns)

- `RenderWebinar` currently renders nothing (refactor in progress).
- `DialogContent`'s `isHideCloseButton={true}` actually **shows** the button.
- `CountdownTimer` ticks every 50 ms; once a second is enough.
- Remaining lint warnings are mostly unused imports (`import React`).
